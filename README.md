# 高温大学駅伝速報

## エージェント運用

このプロジェクトでは `agmsg` のチーム `Ekiden` を使用します。

| エージェント | 担当 |
| --- | --- |
| `leader` | 要件定義、調査、設計、実環境テスト、レビュー、ドキュメント作成・更新 |
| `corder` | 設計に基づく実装、単体テスト |

実装を伴う依頼では、`leader` が要件・受け入れ条件・設計を整理して `corder` に委譲します。`leader` は実装を直接変更せず、`corder` の成果物をレビューし、実環境に近いテストと文書化を担当します。

### 通知機能の作業フロー

1. `leader` が通知経路を調査し、再現条件と受け入れ条件を定義する。
2. `leader` が `corder` へ実装・単体テストを依頼する。
3. `corder` が変更と単体テストを実施し、結果を `agmsg` で報告する。
4. `leader` が差分レビュー、構文確認、実環境テスト、ドキュメント更新を行う。

通信には以下を使用します。

```text
team: Ekiden
leader: 要件定義・調査・設計・実テスト・文書化
corder: 実装・単体テスト
```
