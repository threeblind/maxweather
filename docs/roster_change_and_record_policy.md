# エントリー変更・個人記録の運用方針

## 目的

大会期間中に区間エントリーや交代が続く場合でも、現在のエントリーと実況表示を一致させる。区間変更前の選手に誤って付いた個人記録は、履歴として残さず削除する。

## 正本

- 監督から提示された最新の区間表を正本とする。
- `config/ekiden_data.json` の既存内容から、次の区間表を推測して正本にしてはいけない。
- 交代指定がある場合は、区間表に交代を適用した後の状態を現在のエントリーとする。
- 補欠欄の括弧書きは、すでに別区間へ登録済みの選手として扱い、補欠には重複登録しない。

## 個人記録の扱い

`data/individual_results.json` は、現在のエントリー選手の記録だけを保持する。

区間変更・交代で選手が現在のエントリーから外れた場合は、その選手について次を空にする。

- `totalDistance`
- `records`
- `legSummaries`

実際に過去に走った記録であっても、現在のエントリーから外れた選手の履歴として保存しない。選手エントリー自体を削除する必要はなく、将来再登録される可能性を考慮して空の選手レコードは残してよい。

## 更新手順

1. 最新の6〜10区、補欠、交代指定をそのまま転記する。
2. 交代を適用し、最終的な区間順を確定する。
3. `currentLeg` が6なら、現在走者が確定区間表の6区選手であることを確認する。
4. 変更前選手の個人記録を削除する。
5. 変更後選手のレコードを用意し、実況更新で新しい記録を付ける。
6. `realtime_report.json` の `runner` と `nextRunner` が区間表と一致することを確認する。

## 必須チェック

- 監督提示の区間表と設定の6〜10区が完全一致する。
- 期待値は設定ファイルから生成せず、提示内容から独立して作る。
- 1区ずれた区間表を検出できる。
- `currentLeg=6` なら、実況の走者名が6区選手と一致する。
- 現在の6区選手以外に、当日の6区記録が残っていない。
- 変更前選手の `totalDistance`、`records`、`legSummaries` が空になっている。
- 区間表にない選手、補欠との重複、同一選手の複数区間登録を検出する。

## 今回の教訓

名古屋大学と学連選抜では、区間表を1つずつずらした期待値を検証側にも登録していたため、実装と検証が同じ誤りを共有していた。また、変更前選手の記録を残すことを前提にしていたため、豊田などの誤った6区記録を検出できなかった。

今後は「最新提示内容との完全一致」と「現在のエントリー外の個人記録が存在しないこと」を別々に確認する。
