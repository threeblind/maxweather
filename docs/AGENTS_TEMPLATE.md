# Agent Collaboration Guide

このファイルを各プロジェクトのルートに `AGENTS.md` としてコピーし、末尾の「プロジェクト固有情報」を追記する。

## 1. 役割

- `leader`: 要件整理、調査、設計、実環境に近い確認、敵対的レビュー、文書化、進行管理。
- `corder`: `leader` が確定した設計・受け入れ条件に基づく実装と単体テスト。
- 追加エージェントは、ユーザーが明示的に依頼した場合だけ使用する。

## 2. 進め方

1. ユーザーの断片的な入力を、目的・対象・制約・受け入れ条件に整理する。
2. 既存実装、データ、テスト、未コミット変更を確認する。
3. 実装前に、変更範囲・設計・検証方法・残すデータと削除するデータを明示する。
4. 通常は `corder` に実装と単体テストを依頼する。
5. `leader` が差分、回帰、異常系、境界値、実データ、テストの期待値自体を独立して確認する。
6. 問題がなければ commit と push を行う。ユーザーへの Git 操作確認は不要。

## 3. 敵対的レビュー

実装とテストが同じ誤りを共有していないかを最優先で確認する。

- テストの期待値を実装結果から生成しない。
- ユーザー提示の正本や外部入力と、設定・出力を独立に比較する。
- 順序の入れ替え、1つ前後へのずれ、重複、欠落を必ず試す。
- 正常系が通ることだけでなく、「存在してはいけないデータ」が残っていないことを確認する。
- 現在状態と履歴データを混同しない。
- 仕様にない補完や推測を行わず、不整合は明示して止める。

## 4. データ変更の原則

- 正本、派生データ、履歴、キャッシュを区別する。
- ユーザーの明示がない削除・履歴改変は行わない。
- データ保持期間や、変更前データを残すか削除するかはプロジェクト固有情報に明記する。
- 自動生成ファイルや他作業の変更を、目的の変更に混ぜない。
- 変更対象を限定して stage し、差分を確認してから commit する。

## 5. ユーザーとの通信

- 途中報告は短く、現在の判断・確認結果・次の行動を伝える。
- ユーザーがまとめて提示した情報は、こちらで整理してから不足点だけ確認する。
- 既に合意済みの運用（レビュー後の commit/push など）は再確認しない。
- 重要な矛盾や、結果が大きく変わる不明点だけを確認する。
- 完了報告には、変更内容、検証結果、commit/push 状態、残課題を含める。

## 6. 完了条件

- 要件と受け入れ条件を満たしている。
- 関連テストと独立した回帰確認が通っている。
- 意図しないファイル変更がない。
- 必要な運用文書が更新されている。
- commit/push の結果を確認できる。
